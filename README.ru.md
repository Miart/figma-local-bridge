# Figma Local Bridge

Локальный MCP-мост: **OpenCode ↔ MCP (stdio) ↔ WebSocket ↔ плагин в Figma Desktop**.

Даёт доступ к **открытому файлу** в десктопном Figma (слои, дизайн-контекст, скриншоты, экспорт, переменные, поиск по дизайн-системе) — **без Dev Mode**.

Официальный сервер Figma (`127.0.0.1:3845`) требует Dev/Full seat на Professional+. Здесь вместо этого свой плагин: в `plugin/manifest.json` стоит `editorType: ["figma","figjam"]`, а не `devid`, поэтому он исполняется в обычном редакторе.

---

## Архитектура

```
Figma Desktop ──WebSocket──▶ daemon (порт 8787, один на всю машину)
                                  ▲
                                  │ WebSocket-клиент
            ┌─────────────────────┼─────────────────────┐
      MCP-процесс           MCP-процесс           MCP-процесс
      (сессия A)            (сессия B)            (сессия C)
            ▲
            │ stdio
        OpenCode
```

Демон существует не для красоты:

- плагин спарится **только с одним сокетом**;
- CSP-манифест Figma умеет allowlist'ить только **фиксированные** origin, поэтому порт не может быть эфемерным;
- но OpenCode спавнит по одному MCP-процессу на рабочую директорию — на фиксированном порте они бы столкнулись.

**Один демон = один сокет = один порт = один токен = один импорт плагина.**

## Запуск

### 1. Демон

Автозапуск на macOS через launchd (`RunAtLoad` + `KeepAlive`) — пример unit-файла:

```
~/Library/LaunchAgents/local.figma.bridge.daemon.plist
```

Вручную (например, после падения):

```sh
cd <repo>   # каталог, куда склонирован проект
npm run daemon          # или: node server/dist/daemon.js
```

Лог: `/tmp/figma-bridge-daemon.log`

Состояние:

| Файл | Назначение |
|---|---|
| `~/.local/share/opencode/figma-bridge-daemon.json` | pid, порт, clientKey, токен |
| `~/.local/share/opencode/figma-bridge-daemon.secret` | персистентный токен плагина (`0600`) |

Токен **не меняется** при перезапуске демона — вставь его в плагин один раз.

### 2. Импорт плагина (один раз)

В Figma: **Plugins → Development → Import plugin from manifest…**
→ `<repo>/plugin/manifest.json`

### 3. Запуск плагина (каждый раз)

**Plugins → Development → Figma Local Bridge**

Токен вставляется **один раз** и лежит в `figma.clientStorage`, плагин сам
переподключается при каждом запуске. Порт задан в `plugin/manifest.json`
(`devAllowedDomains`) — поле в панели его не меняет, менять нужно манифест.

### Что показывает панель плагина

| Строка | Смысл |
|---|---|
| статус | `connected` / `offline — retrying in Ns` / `token rejected` / `another Figma window holds the plugin slot` |
| `page`, `selection` | что открыто и что выделено сейчас. Плагин шлёт это сам, поэтому строка живая и без соединения |
| `mcp` | сколько MCP-сессий подключено к демону (0 = opencode не привязан) |
| `last` | последняя ошибка вызова (полный текст — в подсказке при наведении) |
| счётчик справа сверху | сколько вызовов прошло через панель; краснеет после ошибки |

Без запущенного плагина MCP-сервер поднимется, но все инструменты будут отвечать `FIGMA_BRIDGE_OFFLINE`.

## Три слоя «connected» — не путать

`opencode mcp list` показывает `✓ connected`, когда MCP-хендшейк по stdio прошёл. Это **не** значит, что плагин спарен.

| Слой | Что означает | Проверка |
|---|---|---|
| `opencode mcp list` → `connected` | node-процесс поднялся, инструменты перечислены | `opencode mcp list` |
| `DaemonLink.connected` (`link.ts`) | сокет MCP-клиента к демону открыт — про Figma ничего | — |
| `Daemon.hasPlugin` (`link.ts`) | плагин реально спарен | `figma_ping` |

Живая проверка третьего слоя:

```sh
lsof -nP -iTCP:8787 | grep ESTABLISHED
# строка, где peer — процесс Figma, а не node: это плагин
```

Раньше демон угадывал `connected` по состоянию своего сокета и показывал «connected» вообще без плагина. Теперь авторитетный ответ присылает демон при регистрации клиента.

## Конфигурация OpenCode

```jsonc
"figmaBridge": {
  "type": "local",
  "command": ["node", "/path/to/figma-local-bridge/server/dist/index.js"],
  "environment": {
    "FIGMA_BRIDGE_PORT": "8787",
    "FIGMA_BRIDGE_WRITE": "1",
    "FIGMA_BRIDGE_DESTRUCTIVE": "0"
  }
}
```

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `FIGMA_BRIDGE_PORT` | из `plugin/manifest.json` (`8787`) | Порт демона |
| `FIGMA_BRIDGE_HOSTS` | `127.0.0.1,::1` | Интерфейсы |
| `FIGMA_BRIDGE_INFO_FILE` | `~/.local/share/opencode/figma-bridge-daemon.json` | Файл состояния |
| `FIGMA_BRIDGE_TOKEN_FILE` | `~/.local/share/opencode/figma-bridge-daemon.secret` | Персистентный токен |
| `FIGMA_BRIDGE_WRITE` | `1` | `0` — read-only |
| `FIGMA_BRIDGE_DESTRUCTIVE` | `0` | `1` — разрешить `figma_use` |

**Не переименовывай сервер и не поднимай второй экземпляр моста.** Плагин спарится ровно с одним сокетом; второй демон вытеснит первый (`4409 already paired`), и `figmaBridge` отвалится.

Порт по умолчанию берётся из `plugin/manifest.json` (`networkAccess.devAllowedDomains`), потому что Figma пускает плагин только на origins из манифеста: демон на другом порту для плагина просто не существует. `FIGMA_BRIDGE_PORT` всё ещё перекрывает манифест (нужен тестам и второму демону), но при расхождении демон пишет об этом в лог прямым текстом.

## Разработка

```sh
npm run build          # plugin (esbuild) + server (tsc)
npm run typecheck      # server (tsc) + plugin (tsc, @figma/plugin-typings)
npm test               # собирает артефакты и прогоняет ВСЁ: unit + e2e
```

`npm test` сначала пересобирает `server/dist` и `plugin/*.mjs`, потому что тесты импортируют именно их: тест, читающий устаревший артефакт, зеленеет на коде, которого Figma не увидит. Файлы гоняются с `--test-concurrency=1` — e2e поднимают демонов на портах и делят один secret-файл, параллельный запуск делает их флакующими.

Тесты: `test/` — `commands.test`, `fingerprint.test`, `scope.test`, `retry.test`, `offline.test`, `dispatch.test`, `daemoninfo.test`, `use-figma.gate.test`, `use-figma.safety.test` (unit, 143 проверки) и `daemon.e2e`, `link-state.e2e`, `mcp.e2e`, `tools.e2e` (e2e, 47 проверок). Регрессии, которые портят файл тихо, покрыты отдельно: ретраи — `retry.test.mjs`, офлайн — `offline.test.mjs`, диспетчер плагина — `dispatch.test.mjs`, таймаут и смена страницы — `use-figma.safety.test.mjs`, дескриптор демона — `daemoninfo.test.mjs`.

## Устойчивость

Figma выгружает UI плагина, когда приложение уходит в фон. Браузер рвёт сокет без close-фрейма (код 1005), плагин переподключается — и всё это время запросы в полёте висели до своего таймаута (30–115 с) с невнятным сообщением.

Что сделано:

| Проблема | Решение |
|---|---|
| Запрос в полёте при обрыве плагина висел до таймаута | `FigmaClient` отменяет все pending-вызовы сразу, как только приходит `link: connected=false` |
| Вызов, попавший в окно переподключения, падал | `call()` ждёт до 2 с, пока плагин спарится заново, и только потом отказывает |
| Вызов при отсутствии плагина стоил 30 с (15 с в `callOnce` + 15 с в ретрае) и врал о причине | Ожидание ограничено одной грацией в 2 с; запрос, который не ушёл, **не отправляется вообще** и падает сразу как `BridgeNotPaired` |
| Нет дескриптора демона → `index.ts` подсовывал `DaemonLink` на порт 0, который не может подключиться никогда | Явный `OfflineLink`: `connected=false`, `send()` сразу называет причину («the bridge daemon is not running») |
| Замерший iframe плагина оставлял зомби-сокет | Демон пингует сокет раз в 15 с; нет pong — сокет терминируется, плагин спаривается заново |
| Фиксированные 2 с ожидания на каждый обрыв | Backoff 400 мс → 15 с + джиттер; первый реконнект почти мгновенный |
| Реконнект-луп: `connect()` закрывал старый сокет, но его `onclose` оставался подписан → новый `connect()` → снова закрывал только что открытый сокет, по кругу | Обработчики отсоединяются **до** `close()`, плюс проверка `socket !== sock` против гонок. Луп давал ~4 переподключения в секунду и 1005 без close-фрейма |
| Сокет открылся и сразу умер → задержка сбрасывалась в пол, и Figma-цикл бил по демону каждые 400 мс | Задержка сбрасывается только если соединение прожило >10 с; иначе растёт. Панель считает секунды до переподключения: «Figma reloaded the plugin — retrying in 2.4s» |

### Идемпотентность ретраев

Figma рвёт сокет в середине вызова. Клиент не знает, применился код или нет, и повторяет запрос — а повторный `use_figma` заново исполняет тот же сниппет и оставляет дубликаты всего, что создал. На практике это дало десятки лишних компонентов в документе.

Поэтому `opId` минтится **один раз на логическую операцию** и переиспользуется всеми попытками (`server/src/figma.ts` → `call()`). Плагин держит ограниченный кэш `opId → результат` и на повтор **не трогает документ**, а проигрывает записанный ответ с `replayed: true`.

Кэш живёт в `plugin/dispatch.ts` — отдельном модуле без единой ссылки на `figma`, чтобы его можно было тестировать вне песочницы (как `scope.ts`). Он закрывает две дыры, обе портят документ молча:

| Дыра | Что было | Что стало |
|---|---|---|
| Повтор приходит, пока первая попытка ещё **исполняется** | В кэш записывалось только по завершении, поэтому повтор находил пустой кэш и запускал тот же сниппет второй раз, параллельно | Запись — это Promise, созданный в момент диспатча: повтор присоединяется к идущему вызову и получает его ответ |
| Две мутации в полёте одновременно | `figma.commitUndo()`/`triggerUndo()` помечают **один глобальный** undo-барьер: два параллельных вызова откатывают работу друг друга, а падение одного ревертит правки другого | Мутирующие методы выстроены в цепочку: строго по одному. Чтения остаются параллельными |

Список мутирующих методов — `MUTATING_METHODS` в `plugin/tools.ts` (плюс `replace_repeated_with_component` в `code.ts`). **Новый пишущий метод обязан быть там**: автоматически это не проверяется, `dispatch.test.mjs` ловит только опечатку в имени.

`rev` двигается и на ошибке: провалившийся вызов мог успеть записать и откатиться, а откаченный документ — не то состояние, которое агент снял последним скриншотом.

Дополнительно ошибка обрыва различает два случая, потому что опасны они по-разному:

| Ситуация | Что в сообщении | Что это значит |
|---|---|---|
| Сокет умер до отправки | `disconnected before <method> was sent` | Ретрай безопасен, документ не тронут |
| Сокет умер в полёте | `may or may not have been applied` | Ретрай идёт под тем же `opId` и не применит код дважды |

Когда бюджет ретраев исчерпан, итоговая ошибка **сохраняет первое, самое информативное сообщение** и дописывает, что стало с последней попыткой и с каким `opId` — иначе оператор увидел бы безобидное «is not connected» и не понял бы, что в документе может лежать лишнее. Она сознательно **не** утверждает «unattempted»: если запрос успел уйти, никто не знает, применился он или нет.

Отдельно про быстрый отказ. Ожидание ограничено одной грацией (`LINK_GRACE_MS = 2000` в `server/src/figma.ts`), и состояние спрашивается раздельно:

| Состояние | Что делает `call()` | Почему грация именно такая |
|---|---|---|
| Сокета до демона нет (`link.connected === false`) | ждёт до 2 с, потом `the client has no socket to the bridge daemon; <method> was not sent` | `DaemonLink` переподключается сам, первый реконнект ≈ 1 с |
| Сокет есть, плагин не спарен (`linked === false`) | ждёт до 2 с, потом `no Figma plugin is paired with the bridge; <method> was not sent` | перезагрузка UI плагина занимает сотни мс |
| Обрыв в полёте | ждёт до 2 с; если плагин вернулся — повтор под тем же `opId`, если нет — ошибка с первым сообщением | 2 с хватает на флап; ждать 15 с бессмысленно, если Figma в фоне и вернётся только по действию пользователя |

`BridgeNotPaired extends BridgeOffline` — это внутренний различитель: `call()` не тратит бюджет ретраев на запрос, который даже не был отправлен. Для агента и e2e сообщение по-прежнему помечено кодом `FIGMA_BRIDGE_OFFLINE`.

### Стухшие скриншоты

Figma отдаёт закешированную картинку после изменения документа, и инвалидировать кэш из Plugin API нельзя. Поэтому `get_screenshot` возвращает `rev` — счётчик завершённых вызовов. **Одинаковые байты при разных `rev` означают, что рендер залип, а не что правка ничего не сделала.** Подпись под картинкой несёт `rev` прямо в ответе инструмента, чтобы это было видно агенту, а не лежало в логе.

`rev` и `replayed` едут на уровне конверта, а не внутри результата, поэтому у `FigmaClient` есть `callWithMeta()` — `call()` остался тонкой обёрткой, чтобы не менять 17 существующих вызовов.

Контракт ретраев покрыт в `test/retry.test.mjs` (6 тестов), контракт офлайна — в `test/offline.test.mjs` (5 тестов), диспетчер — в `test/dispatch.test.mjs` (11 тестов): все три регрессии портят файл тихо, а не с грохотом.

### Что ещё мешало и что с этим сделано

| Симптом | Причина | Решение |
|---|---|---|
| `changed: 0` после перемещения/ресайза | сигнатура была `type + name + childCount + textLength` — геометрия не входила | геометрия добавлена в сигнатуру; заодно узел, вытащенный за пределы scope, больше не проходит мимо containment-проверки |
| `indexTree` тормозил на странице в 10k узлов | `n.children` читался трижды на узел (сигнатура + обход), а под `dynamic-page` каждое чтение может форсировать загрузку | список детей читается один раз и переиспользуется |
| Непонятно, что именно занимает время в вызове | тайминги не измерялись | в ответе `ms: {code, index, total}` и `nodes: {before, after}` — если `index` близок к таймауту, страницу надо дробить, а не гонять одним вызовом |
| `plain()` молча отбрасывал `width`, `fills`, `layoutMode` | нода схлопывалась до `{id, type, name}` ради дешёвой сериализации | `verbose: true` отдаёт курируемый список полей; дефолт прежний, чтобы не платить за это на 10k узлах |
| Таймаут `use_figma` откатывал документ, а сниппет продолжал исполняться и **дописывал после отката** | `Promise.race` перестаёт ждать, но код живёт: откат возвращал старое состояние, зомби писал поверх него, агенту при этом говорили «(rolled back)» | таймаут **не** откатывает: сообщение говорит «NOT rolled back: the code is still running and may still write — inspect the scope before trusting it». Обычная ошибка по-прежнему откатывается |
| Сниппет внутри `use_figma` мог уйти на другую страницу и править там | guard индексирует **одну** страницу: `figma.setCurrentPageAsync()` уводит землю из-под diff'а, а round trip (ушёл, поправил, вернулся) оставляет проиндексированную страницу байт-в-байт идентичной | ловится событием `currentpagechange`: переключение страницы в вызове = нарушение, вызов отклоняется и откатывается, подсказка своя («one call per page, or use figma_set_page first») |
| `getNodeByIdAsync` отдавал удалённую ноду, и она отвечала как живая | кэш Figma не инвалидируется | проверка `node.removed` — инструмент теперь честно падает вместо того, чтобы сообщать состояние несуществующего узла |
| Каждый ответ плагина уходил **всем** MCP-клиентам | демон рассылал любое сообщение от плагина широковещательно; при нескольких сессиях каждая разбирала чужие скриншоты (base64, ~100 КБ) | id запроса неймспейсится клиентом (`<cid>:<id>`, см. `DaemonLink.send`), и демон адресует ответ владельцу; неизвестный префикс по-прежнему рассылается — лишний кадр дешевле повисшего вызова |
| Битый дескриптор демона принимался как живой | `readDaemonInfo` проверяла только `ws` и `pluginToken`: файл, обрезанный на середине записи (демон убили), читался как «демон с URL `undefined`», а отсутствие `pid` заставляло реконнект считать состояние изменившимся на каждом обновлении | проверяются все поля; мусор читается как «демона нет», и вызывающий сообщает об этом честно |
| `unhandledRejection` съедал стек | `String(e)` терял единственную строку про место падения | в лог идут pid, стек и подсказка для `BridgeOffline`; выход оставлен — половина моста хуже честного перезапуска |

### Чего бридж не умеет

Честно про границы, чтобы не тратить на них время:

- `indexTree` обходит **всю** страницу дважды на вызов. Ускорение убирает лишние чтения, но не делает индекс инкрементальным: кэш между вызовами был бы небезопасен, потому что пользователь правит файл в Figma параллельно. На очень большой странице единственный выход — дробить работу.
- Скриншоты кэширует сам Figma. `rev` лишь делает это **видимым**, но заставить Figma перерисовать нельзя.
- `use_figma` отдаёт `figma` целиком — это не sandbox, а «заметить и откатить». Код, который срабатывает после возврата (fire-and-forget промисы), от diff'а уходит; поэтому таймаут не откатывается, а честно говорит, что код ещё жив. Отдельно закрыт самый широкий вариант этого: переключение страницы внутри вызова (`currentpagechange`) — иначе можно было править страницу, которой guard не видит.

Проверить живость: `lsof -nP -iTCP:8787 | grep -i figma` — пусто, значит плагин не спарен.

## Диагностика

| Симптом | Причина |
|---|---|
| `FIGMA_BRIDGE_OFFLINE` | Плагин не запущен в Figma либо демон упал |
| `figma_ping` → `connected: false` | Плагин не спарен |
| Демон не поднимается | Порт 8787 занят — `lsof -nP -iTCP:8787 -sTCP:LISTEN` |
| `4409 already paired` | Второй экземпляр моста; убей лишний процесс |
| `4403 bad key` | Демон перезапустился и выдал новый clientKey; перезапусти OpenCode |
| `4401 bad token` | Токен в плагине не совпадает с `figma-bridge-daemon.secret` |
| Плагин перестал подключаться после перезапуска демона | Должен подхватиться сам; если нет — перезапустить плагин в Figma |
